# Optimizer workload assets

These empty-schema, plan-focused fixtures are reproducibly generated by
`../import_optimizer_workloads.py`. Each workload manifest pins its upstream
repository commit and source paths. Tests consume these checked-in files;
network access and source clones are only needed when regenerating them.

- `tpch`: 22 generated TPC-H queries, 250 SQLStorm queries, and the PostgreSQL
  `pg_tpch` schema.
- `tpcds`: 103 generated TPC-DS statements, 250 SQLStorm queries, and the
  PostgreSQL `pg_tpcds` schema.
- `job`: the 113-query Join Order Benchmark plus 250 SQLStorm queries.
- `sqlstorm`: 23 semantically validated StackOverflow queries plus 250
  structurally distinct SQLStorm queries.

The fixtures intentionally contain no benchmark data. They validate planning,
rule provenance and empty-input outcomes; populated result equivalence is a
separate workload run against the same SQL assets.

Run one checked-in query with:

```sh
python3 test/dsl/run_workload_comparison.py --pg-config /path/to/pg_config \
  --audit-bin build-ninja/pgorca_rule_audit -t tpch/q01
```

Run only the 1,000-query SQLStorm sample with `-t '*/s*'`.
The comparison uses `bounded_expansive_cbo.policy` by default; pass
`--unbounded` when diagnosing the complete DSL search space.

Redistributed source licenses are preserved under `licenses/`. The JOB files
are attributed to the Join Order Benchmark repository in its manifest.
